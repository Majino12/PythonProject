VTuberProject 0.16.0 — release validation, 2026-11-06 (Asia/Seoul)

Scope: the existing short-haired 2D studio, based on the released 0.15.0 artwork. This iteration improves four areas: authored motion timing, verifiable asset inventory, tracking controls and numerical replay, and an independent local output page. It does not claim that the complete long-term product or one-image character generation is finished. No 3D or VTube Studio work was added.

Changes:
- Natural/quick motion profiles use separate eye-opening/closing and jaw-opening/closing timing. Authored special mouth shapes pass through the actual neutral painting. Reversals start from the displayed state, and continuous manual input retains elapsed hold time. No image interpolation, warping, crossfade or new artwork is introduced.
- character-pack.json inventories nine poses, 123 selected PNGs and 135 files with byte lengths and SHA256. It registers source manifests, crops, anchors, gaze, approval scope and explicit gaps. Browser startup verifies metadata and checks loaded layers; full artwork-byte hashing belongs to the complete file-verification checks. This inventory is not a generic character importer, packed model, new renderer, or a new approval.
- Balanced/responsive/stable tracking presets and 0.7–1.4 blink/mouth sensitivity reuse FaceSession's single existing filter. Nine-direction pose confirmation requires fresh inference samples. Existing calibration can be restarted. Inference rate/cost and face-signal staleness are measured separately from successful canvas drawing.
- Numeric clip recording is explicit and memory-only, bounded to 60 seconds, 1801 samples and 2 MB. Its exact schema contains timestamped full 22-channel coefficients and prepared pose IDs, not image/audio/model data. Replay closes the camera and uses recorded timestamps plus the currently selected painted-motion profile; it is not pixel-identical video playback. Imports reject unknown fields, missing channels, invalid ranges and non-monotonic timestamps.
- short-hair-output.html receives the displayed state through the same loopback HTTP/SSE service, across browser processes. Its output canvas is fixed at 1280x720. The visible controller must explicitly enable output; a one-second heartbeat keeps static output active. Explicit stop clears the receiver. The relay sends a status heartbeat every second and marks the source stale after more than five seconds without a controller update. A stale source or receiver connection error preserves the last drawn frame with a bottom-right signal-interruption notice; new data hides that notice. Slow delivery replaces pending old states with the latest state. The receiver requests no camera or microphone.

VTuberProject 0.15.0 — release validation, 2026-10-28

Default: short-haired 2D avatar studio with nine prepared head poses, painted eye/mouth/brow expressions, independent gaze, 22 ARKit-named coefficients, optional camera tracking and local project/JSON/PNG/video export. No 3D changes in this release.

Changes in 0.15.0:
- Eight non-front poses now have five eye-opening and jaw-opening stages instead of three, using 16 selected new source portraits. Front retains its existing five stages.
- Eye and jaw motions advance through adjacent prepared artwork, including reversals from the currently displayed stage. This does not synthesize missing art by stretching or crossfading.
- The studio offers 30/60 fps targets, reports successful drawing measurements and uses the selected target for video capture. Requested fps is not guaranteed output or a count of distinct source drawings.
