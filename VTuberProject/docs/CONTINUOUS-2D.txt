连续 2D 转头：实现、验收与边界

这一轮以现有九张方向原画为端点，加入连续 yaw / pitch 坐标。坐标范围 -1 至 1 表示素材覆盖的九宫格，不是物理角度，也不意味着任意角度都有独立画稿。端点使用对应原画；“透明”只另行应用角色遮罩，原始 PNG 文件不被改写。

运动来自真正的 RIFE v4.25 神经网络。开发阶段对 16 条相邻边分别运行 7 个时间位置，共 112 次推理，提取到两张端点画稿的反向位移场，以及两者的遮挡权重。输入分辨率为 576×720，保存的运动场为 144×180：位移采用四通道 float16，遮挡权重采用 uint8。固定模型提交、权重校验、原图校验和每个字段文件的校验均记录于 assets/short-hair-motion-v1/manifest.json。

浏览器读取这些预计算结果，将当前眼、口、眉和视线合成到端点画稿上，再通过 WebGL 2 按运动场重投影并合成。RGB 与透明 alpha 使用同一个位移场和同一组权重，减少头发边缘出现颜色与遮罩各自移动的情况。默认启动不下载权重，也不在直播期间运行 RIFE 推理；本轮发布包只含运动场和复现脚本。

这与未对齐画稿的透明叠化不同。两张图先按模型估计的运动对齐，再按遮挡权重组合。时间采样之间通过运动场插值得到连续变化；端点之间能够连续控制，并不等于每个角度都重新调用了神经网络。

九宫格被划分为八个三角形。边界使用对应的两帧模型结果；三角形内部将相邻边的位移和可见性作几何推广。这部分是基于模型运动场的实时近似，不是 RIFE 对三张输入的直接神经推理。文档、界面和验收不得把两者混称。

透明层用于从原图中分离角色及可见部件。仅将页面 CSS 设为透明不能去除画稿背景；输出必须实际使用带 alpha 的角色画布。原始素材中被遮住的头发、颈部或服装没有因此获得新的完整画稿；大幅度独立摆动仍需要相应补画。PNG 和 OBS 浏览器源可以承载透明画面，但录像编码器是否保留 alpha 必须另行验证。

v0.19 比较覆盖全部16条边×7个时刻。4.25 全分辨率运动场重建模型RGB的内部误差均值约2.68e-7；相同144×180字段压缩后，原图尺寸脸部误差从4.6的0.00285增至0.00407，alpha从0.000406增至0.000631。反向RGB一致性平均误差从0.01232降至0.01083，15/16边改善，但right→right-down退步。实际中点接触表中，左上→正面、正面→右下、下→右下的双眉/发线重影减少，部分细线略软。采用4.25是综合画面选择，不表示所有指标获胜，也不是用户逐稿批准。原有v0.17指标仍保留为历史；详见validation/v0.19-rife-model*与模型构建说明。

仍需关注的实际限制：
  1. 不同方向原稿中的发丝、衣褶和比例不完全一致，插值仍可能在局部产生形变。
  2. 运动场由中性画稿估计，动态表情沿用这一运动；极端复合表情需要逐项观察。
  3. 144×180 的低分辨率场经过上采样，细线与遮挡边缘是近似结果。
  4. 三角形内部的几何推广与两帧模型直出不同，应检查连续拖动及快速反向，而非只看九个端点。
  5. 渲染需要 WebGL 2；目标 60 fps 不等于所有设备、真人跟踪和 OBS 链路都能稳定达到 60 fps。

复现方式与许可：
  以 tools/RIFE-BUILD.txt 中的现行4.25步骤、固定下载与SHA256为准。
  历史compile-rife-fields.py / verify-rife-fields.py只用于旧4.6记录。
  模型来源 https://github.com/hzwer/Practical-RIFE ，许可副本随派生素材保留。
  运行 node --test short-hair-motion-assets.test.mjs short-hair-motion-fields.test.mjs 验证文件、协议与加载行为。


v0.18运行补充
微动是同一RGBA画面上保守的几何位移，含<=1.5px整体摆动、<=2px躯干呼吸、<=2px避开脸部的外侧发梢位移。它不是可编辑独立前后发层，也不是新神经推理。所有输出使用工作台已提交的breath/sway/hair，原画对比强制零微动。全零严格保留v0.17像素；非零在原稿端点也通过单源GPU路径处理。
WebGL上下文恢复重建纹理和程序；丢失期间不清目标canvas。缓存只跟随实际画稿与视线变化，不因无可见变化的系数漂移重绘。端点仅准备一个原稿缓冲。
