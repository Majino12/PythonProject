# MoeMotion 0.11

打开就能体验原创绘制的 2D 角色：内置月见 Luna 使用 13 个预先准备的头部方向、11 段眨眼加开心闭眼、24 种嘴型和眉毛状态组合动作，不需要填写 API Key、安装绘画软件或先学绑定。也可以使用参考配色的 3D 角色进行演示、动捕和录制；不开摄像头也能体验。

**内置分层示例和普通单张图片的能力不同。** Luna 已备好表情与有限方向素材；上传或 AI 生成的普通单图目前只保留静态五官及整体运动，不会自动得到同等的闭眼、张嘴或侧脸画稿。3D 默认使用获得授权的精致 VRM 模板，也保留较轻量的程序化角色。

**精致 3D 是独立制作的模板模型，不是 Luna 或上传图片的三维重建。** 图片用于参考配色，模板的服装、发型和几何细节不会自动变成原图中的设计。

## 启动

安装 Node.js 18 或更新版本，在项目目录运行：

```bash
npm start
```

打开 [MoeMotion 工作台](http://127.0.0.1:4173)。不要直接双击 `index.html`。

内置 2D 表情素材随项目提供，演示不需要调用图像生成服务。首次识别图片或启用摄像头时，需要联网加载 MediaPipe 运行文件和模型；首次切换 3D 时需要加载 Three.js，精致版还会加载 three-vrm 运行库和项目内附带的 VRM 文件。识别、动作跟踪、配色和模型渲染在本机进行。

## 怎么使用

1. **先体验示例**：选择 2D，使用默认月见 Luna 和“自动演示”。如果打开了旧项目，可点击“使用高清分层角色 · 月见 Luna”切回示例；先下载备份保留原角色。
2. **试试表情和方向**：直接点击画面下方的“闭眼”“张嘴”“噘嘴”“抿嘴”“微笑”，再点“恢复动作”。展开“2D 表情精修”可用九宫格与强侧面按钮手动检查 11 个方向；自动跟踪还会使用左右浅转画稿，因此资源合计 13 个方向。“检查过渡”只循环检查眨眼、张嘴、噘嘴和抿嘴，不会播放转头补间；另有眨单眼、挑眉、委屈、圆嘴与逐通道调节。
3. **再换自己的角色**：上传 PNG、JPG、WEBP，或点击“让 AI 帮我画角色”，填写描述和临时 OpenAI API Key。这里得到的是单张图片，当前不会自动生成眼、口、眉或多角度图层。推荐人物居中、正脸、五官清楚的图片；透明 PNG 更适合叠加到其他画面。

“近景 / 完整立绘”调整取景，不会补画素材里没有的身体；新版内置绘制素材是半身像。自动演示提供安静待机、打招呼和说话动作，表情显示受当前素材支持的状态限制。“动作微调”用于整体动作幅度。

想用 3D 时，切换到 3D：精致版提供 VRM 骨骼动作、模型表情与头发物理，轻量版保留程序化外观。“3D 外观微调”可修改发色、服装色和眼睛色。**短发 / 齐肩发 / 长发切换只适用于轻量 3D**，精致 3D 保留原模型发型。

想用真人动作时，点击“开启摄像头”并同意后才会请求浏览器权限。坐姿或摄像头位置变化后点击“重新校准”，自然正视约 3 秒；“关闭摄像头”会停止使用并回到演示。

3D 预览可拖动旋转、双击回正，也支持左右方向键和 Home / 回车 / 空格回正。素材体检中的建议可展开查看。

## 绘制式 2D 表情、方向与精修

v0.11 的内置 Luna 使用 13 张已注册的 1024×1536 方向底图：正面，左右约 20° / 40° / 65°，正面抬头 / 低头，以及左右 40° 的抬头 / 低头。渲染器按输入选择距离最近的真实画稿，并以迟滞避免在边界来回抖动；**不会用像素形变、整脸交叉淡化或程序化 3D 冒充缺失角度**。因此从正脸到强侧面比旧版细致，但仍是有限画稿之间的离散切换，不是连续网格旋转、360° 模型或背面生成。

表情使用与方向相匹配的透明图集：从睁眼到闭眼共有 11 段，另有开心闭眼；嘴部提供 24 个语义状态，覆盖 6 段开口、噘嘴、抿嘴、方向噘嘴、微笑、皱眉和圆嘴。强右噘嘴有一格损坏源稿未采用，运行时固定镜像另一侧的已绘制强噘嘴，因此 24 个可选状态来自 23 个源区域加 1 个固定镜像；这不是随跟踪数值拉伸图片。眉部继续使用 5 种状态。只有相邻的眼部和嘴部画稿会做约 30 / 40 ms 的局部过渡，姿态切换不混合整张脸。

这些是有限状态的组合，不是 52 套独立绘制动作。部分通道会共用口型或眉态，左右嘴角等只能近似表现；视线转动、鼓腮、伸舌没有对应画稿，不会假装生成缺失内容。输入数值和平滑设置可以连续变化，但可见画稿仍由已有帧决定。普通上传图片没有这些图集时，五官保持静态，仍可展示整体动作、取景、截图和录制。

### ARKit 52 是什么

“ARKit 52”在本项目中指的是 Apple 公布的 52 个 `ARFaceAnchor.BlendShapeLocation` **通道名称和 0～1 系数约定**，不是已经连接了 iPhone、TrueDepth 或 ARKit 会话。每个通道可以独立设置输入范围、输出范围、平滑时间，以及线性、平滑、缓入、缓出四种响应曲线；输出范围允许反转。面板会显示实时输入 / 输出值，并提供面部特写，便于观察细微表情。

拖动测试数值或主动勾选“手动试调”会只驱动选中的通道。快捷表情和 JSON 单帧导入可检查多个通道组合；切换下拉通道只是查看，不会破坏整组系数，直到主动拖动测试滑块。内置绘制 2D 的头部方向试调独立于表情：可以固定一张方向画稿后继续换表情，“检查过渡”则循环显示眨眼、张嘴、噘嘴和抿嘴，并不测试姿态补间。它们都是本页的临时诊断输入，会暂时接管相应的 2D 输入，但不会关闭已开启的摄像头，也不会作为动作数据写入项目。点击画面上的试调提示或“恢复动作”即可清除表情、方向和过渡预览；项目只保存各通道的范围、曲线和平滑设置。通道可输入，不等于当前素材已绘制对应表情。

普通浏览器摄像头仍由 MediaPipe Face Landmarker 识别。当前 MediaPipe Tasks 的结果是 `_neutral` 加 51 个与 ARKit 同名的动作通道；MoeMotion 忽略 `_neutral`，并为缺少的 `tongueOut` 输出 0。因此界面采用完整 ARKit 52 schema，并不代表普通摄像头能测出全部 52 项。当前也**不支持从 iPhone 直接接收 ARKit 数据**。

## 保存，下次继续

项目名称、当前角色图片和设置（包括取景、演示动作、2D 表情通道设置、精致 / 轻量模型选择与 3D 外观微调）会自动保存到**当前浏览器的 IndexedDB**，保留一个当前项目。重新打开页面会尝试恢复角色和设置，但动作来源仍为自动演示，不会自动开启摄像头。旧 v1 项目可继续打开，已有图片不会自动变成内置分层角色；未保存模型类型时，默认选择精致版。

- “下载项目”获得 `.moemotion` 备份，之后可用“打开项目”恢复，也可换到其他设备继续。
- 自动保存不可用或失败时，按页面提示下载项目，不要依赖本机存档。
- 清理浏览器数据、使用其他浏览器或更换访问地址，可能无法找到原存档。重要角色请主动下载备份。
- 自动保存和项目备份**不包含 API 密钥、摄像头帧、实时表情系数、手动通道测试值、JSON 单帧测试值或录制视频**。录制和截图需要单独下载。
- `.moemotion` 备份保存用户图片和设置，不复制内置绘制图集或 VRM 文件；在另一设备恢复时仍需使用完整的 MoeMotion 项目。

## 展示和输出

- **截图**：下载当前角色画面的 PNG。选择“透明背景”只移除舞台背景；图片自身的白底等不会自动抠掉。
- **录制视频**：只录制角色画面，**不录音**。浏览器自动选择支持的 WebM / MP4 格式；透明视频的效果取决于编码格式和播放软件。
- **纯净预览**：在当前页面隐藏控制面板，按 Esc 或点击“退出预览”返回。可用直播软件的窗口采集功能采集这个页面；它不是虚拟摄像头，退出按钮等页面提示也可能被窗口采集到。
- **精致版下载 VRM**：输出应用当前配色的 `.vrm`，保留原模型的网格、骨骼、VRM 扩展和许可元数据。部分贴图会附加替换 PNG，原始二进制内容仍保留。导出使用原模型的原始姿态，不包含当前表情、摄像头动作或演示时间线；接收软件对 VRM 的支持程度会影响显示效果。
- **轻量版下载 GLB**：导出中立姿态的 `.glb` 场景，不是 VRM，不包含预录动作。实时跟踪仍由本页面驱动。

## 隐私和能力边界

摄像头画面只在浏览器内处理，不上传服务器，也不会自动保存。导入的本地图片不上传到 AI 服务。使用 AI 生成时，角色描述和临时 API Key 会经由本机服务发送给 OpenAI，可能产生 API 账户费用；密钥不写入项目文件或持久化存储。

绘制式 2D 只在已有配套素材的内置角色上提供眼、口、眉表情和有限方向。图集无法加载时会保留可用的静态图片，不会用形变冒充绘制素材。普通上传 / AI 生成单图可以用于静态五官的整体动画和 3D 参考配色，但当前没有运行时自动拆层、自动补画表情 / 侧脸图集或导入自定义分层角色包的流程。它不是 Cubism 模型；Luna 的左右强侧面也是预先准备的约 65° 画稿，不代表 360° 转面、背面或遮挡后隐藏结构的自动生成。要让其他角色获得同等级的表情与方向，需要另行准备匹配画稿并接入渲染配置。

精致 3D 使用内置的授权 VRM 模板，按图片或手动设置调整配色，利用模型已有的骨骼、表情与头发物理进行动作演示和跟踪；并非从单张图自动生成同款网格或服装。轻量 3D 按图片区域提取配色、参考脸部比例，使用程序化几何组装动漫角色，发型为有限的短发、齐肩发和长发方案。两种模式都不会精确还原图片中被遮挡的身体或背面。

当前**不支持导入用户自己的 VRM**，不生成或读取 Cubism `.moc3`，也不提供自动抠图或虚拟摄像头。项目没有 VTube Studio 连接、插件端口或兼容协议，也不会读取其模型参数；“ARKit 52”只描述本项目内部 2D 表情 schema。光线、遮挡、侧脸角度和身体出镜范围都会影响跟踪效果。模型自身已有的形状、骨骼和表情数量也会限制可表现的动作。

通道命名参考 [Apple ARFaceAnchor.BlendShapeLocation](https://developer.apple.com/documentation/arkit/arfaceanchor/blendshapelocation)。摄像头输出及其差异参考 [MediaPipe Face Landmarker 表情枚举](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/drawing_styles/face_landmarker/Blendshapes) 与 [Face Landmarker 选项说明](https://ai.google.dev/edge/api/mediapipe/python/mp/tasks/vision/FaceLandmarkerOptions)。

## 内置素材与许可

2D 素材在开发阶段使用内置图像生成 / 编辑工具预先制作，不是软件运行时自动调用 API 生成，也不是人工逐帧绘制的声明。`assets/luna-painted-v1/` 保留正面底图和眉图等旧版兼容素材；其来源说明在 `provenance.txt`，`prompts.txt` 是简化的重建提示词，**不是原始生成请求的逐字记录，也不保证复现相同像素**。

v0.11 新增的 18 张 PNG 位于 `assets/luna-painted-v2/`：12 张有限方向底图，加上正面、40° 和 65° 使用的眼 / 口图集。`assets/luna-painted-v2/provenance.json` 记录生成 / 编辑方式、实际提示词、文件生成标识和采用边界，包括拒绝透明通道损坏的修复图、以固定镜像替代一格损坏强噘嘴的说明。素材经过实际 PNG 透明通道、裁切边界和画廊合成检查；生成提示和标识用于来源追踪，不构成复现相同像素的保证。

旧版原创单图 `assets/demo-luna-v1.png` 与 `assets/demo-luna.prompt.txt` 保留用于兼容和备用。上述 2D 素材与精致 3D 模板是独立素材；项目未加入 Live2D / Inochi2D 模型或运行库，也没有导入参考软件的截图素材。

精致版使用 pixiv Inc. 的 `VRM1_Constraint_Twist_Sample`（v1.0.1），项目内文件为 `assets/pixiv-vrm1-sample.vrm`。来源是 [pixiv/three-vrm 的固定提交](https://github.com/pixiv/three-vrm/blob/5a3242b66124386c32b085c6693d9059040e72e5/packages/three-vrm/examples/models/VRM1_Constraint_Twist_Sample.vrm)，另见 [官方样例说明](https://github.com/vrm-c/vrm-specification/blob/master/samples/VRM1_Constraint_Twist_Sample/README.md)。

该模型使用 **VRM Public License 1.0 及文件内许可设置**，不是 three-vrm 软件代码的 MIT 许可，也不是 MoeMotion 独占的原创模型。来源、文件校验值、许可设置和再分发注意事项记录在 `assets/THIRD_PARTY_NOTICES.txt`；模型使用和再分发应遵守其中记录的许可，不要删除出处或把原模型网格、贴图重新声明为 MIT / 公有领域。下载的改色 VRM 保留原模型许可信息，仍受原许可约束。

## 检查和版本

```bash
npm run check
npm test
```

开发验收页位于 <http://127.0.0.1:4173/painted-gallery.html>。它不在主界面提供入口，只读取同一份本地 manifest，用一个渲染器把所有方向依次复制成联系表，并提供表情预设与手动滑杆；不会请求摄像头或访问外网。

v0.11 为内置 Luna 加入 13 个实际方向画稿、11 段眨眼加开心闭眼和 24 种嘴型，并加入方向九宫格、强侧面、表情过渡检查及实际资源验收画廊。方向和表情都只使用已注册画稿：姿态通过最近邻与迟滞选择，相邻眼 / 口帧仅做短暂局部过渡，不做整脸形变或交叉淡化。普通上传 / AI 单图仍是静态五官，3D 模型、许可和导出边界不变。

v0.10 为内置角色加入真正准备好的绘制表情素材：固定区域叠加底图、眼、口、眉帧，沿用 ARKit 52 命名的控制及精修。普通单图改为静态五官与整体运动，明确区分“有配套图集”与“只有一张图片”。未接入运行时自动拆层 / 图集生成，不改变 3D 模型、许可与导出逻辑。

v0.9 加入 ARKit 52 命名的通道处理、实时输入 / 输出、单通道和 JSON 单帧检查、面部特写；当时的单图局部像素形变已由 v0.10 的上述渲染边界取代。仅通道设置随项目保存；没有 iPhone ARKit 或 VTube Studio 连接。

v0.8 加入授权精致 VRM 模板、骨骼和表情驱动、头发物理及配色 VRM 下载；保留轻量 3D 和 GLB 输出，模型类型随项目保存。精致版不是图片重建，也不提供任意 VRM 导入。

v0.7 更新原创示例立绘、原图像素柔和形变和风格化 3D 外观；加入安静待机等演示动作、半身/全身取景、发型与配色微调。测试覆盖动作映射、外观提取、形变、项目数据验证和关键操作生命周期。

v0.6 精简重复入口，加入项目保存/备份、重新校准、截图和纯净预览，修复重复提交及录制冲突；这些功能在后续版本中继续保留。
