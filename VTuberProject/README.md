# VTuberProject · 短发角色 2D 工作台

版本：`0.20.0`。在 v0.19.0 基础上增加九方向前发／脸部分层、遮挡区补画和受保护的局部前发网格，补充透明图层导出与逐方向检查。九方向原稿、已登记表情与批准记录保留；仍为 2D，不接入 VTube Studio，不修改旧 3D。

## 启动与直播

安装 Node.js 18 或更新版本，在完整项目目录运行 `npm start`。打开 [工作台](http://127.0.0.1:4173/short-hair-studio.html)，通过按钮或“左右转头／抬头低头”滑块调整姿态。摄像头与直播默认关闭，需要分别点击启用。

“透明背景”默认开启，预览的棋盘格只属于页面，不写入 PNG 或直播画布。启用直播输出后，在 OBS 添加浏览器源，URL 为 `http://127.0.0.1:4173/short-hair-output.html`，宽 1280、高 720。不要勾选“本地文件”，详见 [OBS-SETUP.txt](./OBS-SETUP.txt)。工作台和输出页需使用同一端口；工作台保持可见以持续跟踪。

开发验收副本使用 `PORT=4180 npm start`。不要因端口冲突直接结束未知进程。

## 连续转头与补帧

头部坐标为 -1–1 的 yaw、pitch，九个原画方向是坐标锚点。手动拖动、演示、摄像头跟随、动作片段和独立输出都使用同一连续姿态。按钮改变目标方向，显示角度通过阻尼从当前位置继续；中途反向、暂停和保存不会重播旧方向队列。摄像头头部坐标连续映射到角色范围，标签所用的最近原稿 ID 不再决定显示角度。

真实 **RIFE v4.25** 在开发阶段处理 16 组相邻原稿，每组 7 个时间点，共 112 次神经网络推理。发布包包含约 26.1 MB 的运动场与可见性数据；运行时不下载权重，不在每个直播帧上运行神经网络。浏览器用 WebGL 2 对当前表情、视线和透明遮罩一起重投影，因此转头过程中仍能眨眼、说话。

两图边上使用模型运动场；二维网格的三角形内部通过几何组合扩展它。这不是三张图直接输入神经网络的结果，也不是用透明叠化代替运动估计。七个时间点之间继续插值运动场。脸部显示使用固定裁切范围，避免旧方向各自裁切导致跳位；全幅保持 1122×1402。原稿锚点直接使用原画路径。

“看原画”显示当前连续角度最近的实际原稿，标题会标明“最近原稿”；关闭后返回连续画面。新推算角度可能出现少量发丝、衣服和轮廓形变，尤其独立原稿差异较大的角度。模型不会创造被遮挡区域的可靠画师分层。实现、误差与复现见 [docs/CONTINUOUS-2D.txt](./docs/CONTINUOUS-2D.txt)、[tools/RIFE-BUILD.txt](./tools/RIFE-BUILD.txt)。

## 自然微动与直播构图

“开启微动”增加轻微呼吸、身体摆动和转头惯性，强度可调。默认关闭；暂停、隐藏页面、保存或导出会冻结当前微动。呼吸与身体摆动保留原有流程，头发微动改为各方向独立前发网格：发根、眼眉与透明边缘固定，内侧发束小幅移动，原位置由补画填充。它仍是局部绑定，未提供完整全头发束编辑。“看原画”始终显示未经微动的原稿。重新打开项目恢复静态微动姿态，不自动开始动画。

直播区提供 16:9 构图预览，可调整 0.5–2.5 倍缩放、水平／垂直位置和镜像。“构图复位”恢复默认居中。构图只作用于独立输出和其预览，角色的头位、方向、原尺寸 PNG 和图层不变。镜像也不改变角色左右通道的含义。工作台发布一次实际完成的微动状态，输出页与片段重放不自行启动第二套微动时钟。

图形上下文丢失时保留最后成功画面，恢复后重新建立纹理和着色器。直播发布遇到临时网络故障会在约 0.25、0.5、1、2、4、4 秒后最多重试六次，恢复时发送最新画面；重试耗尽或另一工作台占用时提示重新启用。静止画面每秒续租一次，不再逐显示帧重复发送。显式停止仍清空输出；服务重启造成的空状态保留旧画面并标明信号中断。

## 透明与素材结构

九张原图分别绑定动漫分割模型生成的 alpha 遮罩。原始 PNG 字节未改；颜色仍取原图，透明度取独立遮罩。全部已有表情先正常合成，再套同方向轮廓；模型转头时 RGB 和 alpha 共用运动场，避免分别抠中间帧产生轮廓游动。灰蓝细发的边缘仍可能保留原背景抗锯齿颜色，可在深色、白色、洋红背景下复核。

“素材覆盖与来源”中的“导出当前方向图层”下载 ZIP：透明角色、互补的头部／躯干可见像素层，以及当前眼、口、眉的局部替换画稿。全部保持原图尺寸和坐标。它导出最近的实际原稿方向，不将模型中间画面冒充原稿分层。局部表情画稿含皮肤和已有遮挡，不能把所有画稿简单相加；头身合成可还原透明角色。图层边界与限制见 ZIP 的 `layers.json` 和 `README.txt`。

“检查当前方向图层”可在棋盘格上逐层查看透明角色、头部、躯干和五官。检查的是点击时最近原稿方向的静态快照；与 ZIP 使用同一构建过程。五官层是替换画稿，不能把八层一起叠加。

v0.20 重新制作了九方向内侧前发与隐区补画，采用 SAM2.1 Hiera Large、逐稿细发修正和保护网格。ZIP 新增 face、frontHair、backHair、contact、edgeCorrection、遮罩与 binding.json；重组顺序和限制以 ZIP 登记为准。脸部底层并非完整无发裸脸，余发也未补全被遮挡后脑。可用 [前发分层与网格检查页](./short-hair-rig-review.html) 查看位移、底层、前景与固定点，详见 [docs/FRINGE-2D.txt](./docs/FRINGE-2D.txt)。v0.18 失败试制仍只保留为历史证据。

“下载完整素材登记”包含原画登记、派生透明遮罩和模型运动场来源。原 `character-pack.json` 仍准确记录 v0.15 原画本身，派生能力单独登记；原稿 candidate/approved 状态不因模型处理或测试自动改变。启动校验模型与遮罩文件 SHA256，并核对与当前原画的来源绑定；完整源图字节核验在测试中完成。

## 表情、跟踪与保存

眼和张嘴沿已有五档画稿推进，保留自然／快速节奏、特殊嘴型经中性衔接、独立视线和 22 个系数。新模型主要解决转头的空间衔接，不把表情画稿数量宣传为每秒 60 张新稿。没有噘嘴与移嘴的复合原稿，正面抬眉仍有整眉近似。

摄像头需主动开启；首次下载 MediaPipe 并请求权限，正脸放松约 3 秒校准。校准要求至少 12 个新样本、至少 1.2 秒有效跨度，并检查最后样本新鲜度、断流、头部稳定、眼睛与嘴巴放松程度；失败或中断保留上次有效校准。大幅头位跳点与失脸重获需两个独立新样本确认，正常小幅动作直接交给连续头位阻尼。识别器发生异常会被释放，下一次启用重新建立实例。识别预算根据实际耗时在 30／20／15 Hz 间调整，绘制帧率独立。平衡／灵敏／稳定预设与眼口灵敏度保留。默认不请求麦克风。真人摄像头、长时间直播与 OBS 实机效果仍需对应设备验收。

“叠加表情”独立于动作来源，摄像头和演示会继续运行。最多保存 8 个有名称的预设，可选择只覆盖眼、口、眉或视线；新启用的同部位预设优先，约 300ms 淡入／退出，退出时回到当前跟踪输入。预设会保存到项目，但激活状态不自动恢复。页面聚焦时按 1–8 切换，Esc 全部取消；输入框、组合键、自动连发和隐藏页面不响应。它不是操作系统全局热键。下面的旧“表情／视线”按钮仍用于手动搭配，会切换到手动来源。片段重放不再二次叠加表情。

“手动待机自动眨眼”默认关闭，只在手动来源运行；使用现有五档眼睑画稿，约 2.8–5.2 秒一次。摄像头和片段保留自己的眨眼。关闭选项逐稿回到当前手动眼睛输入；暂停、隐藏页面、保存和导出冻结当前显示。重新打开项目不会自动播放眨眼。

MediaPipe 识别优先在独立 Worker 中使用 CPU 执行，每次最多一帧在途；异常、取消或超时会释放资源。启动不支持后台推理时明确降级到主线程，界面显示执行位置和结果延迟。超过 240ms 的推理结果丢弃，校准使用采样时间，真实 roll 倾斜角也参与稳定性判断。“闭眼／张嘴输入上限”默认 0.85；校准后本人已做到位但角色幅度不足时，可适度调低。旧项目保留原映射。

动作片段 v3 保存实际显示的连续 headPose、微动三通道、22 系数和时间戳，最长 60 秒、1801 个样本、2 MB；读取 v1／v2 兼容旧方向和连续头位。v3 回放按时间插值已记录的头部坐标与微动，不再二次施加跟踪阻尼。片段不包含摄像头图像或声音。项目和单帧也保存连续角度；新项目保留透明选项，旧项目兼容迁移。导出会冻结当前显示角度；重新打开项目保持静止，摄像头与直播均不自动开启。

项目和单帧导入恢复目标表情系数、连续头角与透明设置，不逐像素恢复保存时的眼口过渡状态；单帧中的实际显示状态用于核对。需要保存那一帧的像素时使用 PNG。

PNG 与 OBS 浏览器源支持真实 alpha。浏览器 WebM/MP4 录像继续使用固定背景，避免不同编码器对透明通道支持不一；需要直播叠加请使用独立输出。30／60 fps 是请求值，实测取决于设备、视窗、当前表情和编码器。

直播状态经本机 HTTP/SSE 发送，慢接收端显示最新状态。停止输出清空画布；超过 5 秒没有工作台心跳或连接出错，保留最后画面并显示信号中断提示。冻结画面不表示跟踪仍工作。

## v0.20.0 验证

自动测试 **989/989**、Python 编译器 **5/5**、真实浏览器 **626/626**（网格与输出 513、连续转头 94、合成 GPU 19）通过。36 张材料 PNG 与九份绑定可确定性重建；模型分割两种重建模式均核对九方向。工作台实际导出 21 项 ZIP，独立画面可接收当前表情和微动。完整记录见 [RELEASE-VALIDATION.txt](./RELEASE-VALIDATION.txt)、[分层与绑定说明](./docs/FRINGE-2D.txt)。

本轮先比对 v0.19 main `1319520e4371dbec29f03c486a6290ac9b0b3a68` 的 679 个发布文件并完整备份 699 个正式文件。局部前发绑定仍不是完全裸脸或全头 rig；部分中间转头角度仍有鼻线、眼睑重影，已保存关闭微动后的复现对照，不能将像素一致性通过当成这类美术问题已经解决。真人摄像头和 OBS 实机尚未在本轮验收。市场对比历史见 [v0.19 对比报告](./docs/MARKET-COMPARISON-v0.19.txt)。
