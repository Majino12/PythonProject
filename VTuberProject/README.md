# VTuberProject · 短发角色 2D 工作台

版本：`0.15.0`。短发角色工作台是默认入口：整合九个准备好的方向、眼睛／嘴巴／眉毛、独立视线、22 个 ARKit 命名通道、可选面部跟踪和本地输出。本次增补八个非正面方向的五档眼睑与张嘴，采用 16 张新选定源稿；正面保留已有五档。新增 30／60 fps 请求选项、实际绘制统计与逐稿动作。

历史素材验收页继续保留；画稿是否获用户确认，以各素材目录的批准记录为准，工作台不会自动写入“通过”反馈。新稿与新行为不因版本号更新而自动获得视觉通过记录。

## 启动与日常使用

安装 Node.js 18 或更新版本，在终端运行：

```bash
cd VTuberProject
npm start
```

打开 [2D 工作台](http://127.0.0.1:4173/)。也可直接访问 [short-hair-studio.html](http://127.0.0.1:4173/short-hair-studio.html)。请通过本地服务打开，不要直接双击 HTML；端口冲突时可运行 `PORT=4176 npm start` 并打开对应地址。

默认端口为 4173。开发验收副本需要在其目录显式运行 `PORT=4175 npm start`，再打开 `http://127.0.0.1:4175/`；这与正式项目是两个独立服务。

1. 从九宫格选择方向，再分别选择眼睛、嘴巴、眉毛和视线；选择另一部位会保留已搭配的动作。“全部放松”清除所有表情，方向不变。眼睑和张嘴按实际准备的档位顺序变化，中途反向从已显示画稿继续；切换方向直接显示新方向的目标表情。
2. “播放演示”循环展示 18 秒动作；勾选“演示时切换方向”会遍历九个准备好的方向。不勾选时固定当前方向。
3. 需要真人驱动时点击“开启摄像头”。首次会下载 MediaPipe 面部模型并请求摄像头权限，随后保持正脸放松约 3 秒完成校准。“摄像头跟随转头”默认关闭，可选择后用头部动作切换有限方向。
4. 默认请求 60 fps，也可选择 30 fps；播放演示或跟踪时显示实际成功绘制的帧率与平均绘制耗时，静止时不报告伪造的实时值。较短手动动作可能不足以形成测量样本。
5. “保存 PNG”和单帧导出会暂停并落到目标表情端点；“看原画”保留输入目标但显示中性原画。“录制动画”只录制角色画面，不录音，沿用开始时所选帧率，录制期间不能更改。停止后下载浏览器支持的 WebM 或 MP4，换方向时录像保持固定画幅。
6. 手动设置自动保存到当前浏览器的本机存储；重要设置用“下载项目”备份，再用“打开项目”恢复。重新打开始终保持静止和摄像头关闭。帧率选择只影响当前会话，重新打开默认请求 60 fps。

“精细控制”提供本角色使用的 22 个 ARKit 命名通道。可粘贴或打开单帧 JSON，也可导出原始系数、实际显示状态和目标状态；输入值必须是 0–1 的数字，未提供通道归零，未知通道明确忽略，非法输入不改变当前动作。这是单帧文件交换，没有 iPhone 数据接收或 VTube Studio 连接。

默认启动只读取随软件提供的本地 2D 画稿，不请求摄像头、不下载识别模型、不加载 3D，也不调用图像生成 API。摄像头画面在本机处理，麦克风关闭；选择表情或方向、切回手动、查看原画、导出、隐藏页面或离开页面会关闭摄像头。页面隐藏时演示和录像也会停止。首次模型下载失败或拒绝权限后仍可继续手动使用并重试。

九个方向是分别准备的画稿之间的离散选择，尚不是连续转头模型。八个非正面方向由三档增加至五档眼睑／张嘴；正面仍为原有五档。动作逐张切换，没有拉伸单图或跨稿透明叠化。正面眉头和眉尾仍共用整眉抬起稿，抿嘴近似整嘴动作。尚无噘嘴叠加左右移嘴的复合画稿，同时输入时选择已有口型，不会生成缺失的组合。各方向的身体、发型和表情幅度存在绘画差异。画稿自身背景会保留在 PNG 和视频中，当前没有自动抠图或虚拟摄像头。

60 fps 是渲染与录像采集请求，不是保证值，也不是每秒 60 张不同原稿。实际绘制受设备与窗口调度影响；屏幕呈现、录像编码和摄像头识别频率分别受各自运行条件限制。页面不把 RAF 回调数或所选目标当作实测帧率。

项目备份只保存本角色的方向、22 个手动系数和查看设置，不包含画稿、摄像头画面、模型、权限或持续跟踪状态，需要与完整软件目录配套使用；与旧 Luna 的 `.moemotion` 项目格式不同。本机存档按浏览器与访问地址隔离，清理浏览器数据后可能丢失，应主动下载备份。

旧 Luna／3D 应用保留在 [legacy-studio.html](http://127.0.0.1:4173/legacy-studio.html)，只作历史兼容与回归检查，不是新角色工作台的启动路径。其旧说明见 `LEGACY-README.md`。新版不会读取或覆盖旧应用的 IndexedDB 项目。

## v0.15.0 验证范围

开发验证使用 Node.js 22：在项目目录运行 `npm run check` 和 `npm test`。GitHub 自动测试也使用 Node.js 22；完整素材与测试夹具均随仓库提供，无需开发机上的外部文件。

- 当前定向自动测试 48 项通过：摄像头生命周期 10 项、工作台生命周期 24 项、时钟与逐稿顺序 14 项；这些测试未开启真实摄像头。
- 最终全套自动测试 589／589 项通过，零失败、零跳过；语法检查通过。测试夹具使用实际基础与扩展素材清单，旧状态和新档位均纳入回归。
- [五档画稿与动作诊断](./frame-motion-diagnostics.html) 已在实际浏览器完成 718 次原生像素比较、1060 项断言，零失败。覆盖九方向五档差异、固定上唇登记、极端视线眼裂边界，以及原有命名状态与独立旧渲染器的像素完全一致。
- 九方向五档对照图已逐张检查，没有发现阻塞使用的拼接问题；这是开发检查，不是新的用户视觉批准。该页可以下载 JSON 与当前方向的原生 PNG 对照图。
- 新素材接入后，右斜下逐稿计时验证全部五档均出现且没有跳档；本次测试负载下，60 fps 请求实测约 55.93 fps，30 fps 请求实测约 30.26 fps。正面此前实测 60.0／30.0 fps；这些结果不保证其它设备达到相同速度。
- 一次 630×460 VP9 录像解析得到 1694 个视频块／28.224 秒，约 59.98 fps。该次录像为新素材启用前的正面测试，不能推定其它方向或负载下的编码速度。

更新原项目时保留完整旧版备份，并校验复制后的文件指纹。完整结果见 [TEST-RESULTS.txt](./TEST-RESULTS.txt) 与各素材的 `validation/` 目录。内部检查不替代用户视觉确认。

本轮没有开启真实摄像头。代码已检查全部 22 通道校准、输入替换、视线归零、权限／模型失败恢复及取消／离页生命周期，但实际设备的跟踪质量仍需要用户使用时确认。重要录像请先点击“停止并保存”，直接关闭页面时不能保证异步下载在卸载前完成。

## 素材与历史记录

角色的眼睛、口型和眉形来自预先准备的有限画稿，视线在各姿态的眼裂内有限移动。素材在开发阶段使用内置图像生成／编辑工具制作，不是软件运行时生成，也不声称人工逐帧绘制；各素材目录的 `provenance.json` 保留来源、提示词和采用记录。批准记录与浏览器反馈分别保存。

[REVIEW-HISTORY.md](./REVIEW-HISTORY.md) 完整保留 review.12 的阶段说明、旧验证结果和当时待办；其中的候选／未覆盖描述是历史状态。[LEGACY-README.md](./LEGACY-README.md) 说明旧 Luna／3D 回归应用。当前 0.15.0 的功能与启动方式以本 README 为准。
