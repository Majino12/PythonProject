# VTuberProject · 短发角色 2D 工作台

版本：`0.16.0`。默认入口仍是短发角色 2D 工作台。本轮在 `0.15.0` 画稿基线上改进动作衔接、整理可核验的角色素材清单、增加跟踪调节与系数片段，并提供独立直播画面页。没有重做现行角色、扩展 3D 或接入 VTube Studio；一张图自动生成完整角色仍是后续目标。

## 启动

安装 Node.js 18 或更新版本，在完整项目目录运行：

```bash
npm start
```

正式服务默认地址：[2D 工作台](http://127.0.0.1:4173/short-hair-studio.html)。请通过本地服务打开，不要直接双击 HTML。端口被占用时先确认正在运行的项目，再使用不同端口；不要直接终止未知进程。

本轮验收副本使用 `PORT=4177 npm start`，地址为 `http://127.0.0.1:4177/`。正式版和验收副本是独立目录与服务，工作台和它的独立画面必须使用同一个端口。

## 本轮新增与日常操作

**动作衔接。** 九方向仍使用实际画稿。每只眼与张嘴各有五档，反向动作从已显示状态继续。“自然／快速”分别调整眨眼、睁眼、开口和闭口的节奏；噘嘴、抿嘴、左右移嘴与张嘴之间经实际中性嘴稿衔接，连续操作不会重置已累积的停留时间。每次最多推进一张，慢帧不补跳。切换方向仍直接进入新方向的目标表情，没有连续转头或新增中间姿态。

**角色素材清单。** “素材结构与覆盖”列出九姿态的眼、口、眉覆盖与批准状态，可下载 `character-pack.json` 清单。登记包含 123 张采用的 PNG、共 135 个带长度与 SHA256 的文件，以及裁切、锚点、视线、来源和缺失能力。浏览器启动核验来源文档，并比对已加载图层；完整画稿字节核验在开发检查中执行。清单不是含全部图片的独立模型包，也不是任意角色导入器；身体、头发和背景仍在底图中，没有因登记而自动分层。

**跟踪与系数片段。** 需点击“开启摄像头”才加载 MediaPipe 模型、请求摄像头权限；保持正脸放松约 3 秒完成校准。平衡／灵敏／稳定预设复用单层通道滤波；眨眼和嘴部灵敏度范围为 0.7–1.4，视线不会随眨眼灵敏度放大。可以重新校准或重置跟踪设置。“摄像头跟随转头”默认关闭，开启后用新推理样本确认九方向切换，避免把重复绘制当作新的转头证据。界面分别显示成功绘制帧率与真实推理次数／耗时，样本不足时保持未测量，人脸信号过期后回归中性。

“记录动作片段”显式记录内存中的时间戳、22 个系数与九方向，可停止、下载 JSON、打开和重放；最长 60 秒、1801 个样本，文件上限 2 MB。片段不含摄像头图像、声音、权限或模型，不会自动保存。录制中可以操作表情和方向；手动操作关闭摄像头后仍可继续该片段。明确暂停、隐藏页面或硬件断连会收尾。重放关闭摄像头，按原时间戳应用系数，动作仍经过当前“自然／快速”节奏；它是系数重放，不是逐像素录像复现。未知字段、缺失通道、越界数值、倒序时间戳等会被拒绝。

**独立直播画面。** 在工作台明确启用“直播画面”，打开 [独立画面页](http://127.0.0.1:4173/short-hair-output.html)，或将工作台显示的地址添加到 OBS 浏览器源。接收画布固定为 1280×720，只有角色画面，不显示控制面板，也不请求相机或麦克风。它通过同一本机服务的 HTTP/SSE 接收状态，可供另一浏览器或 OBS 接收；慢接收端优先显示最新状态。工作台需保持可见，静止时每秒心跳保持输出；明确停止会清空接收画面。超过 5 秒没有新的工作台状态，或接收连接报错时，接收页保留最后一帧并在右下角显示信号中断提示；收到新数据后隐藏提示。冻结画面不代表仍在跟踪。具体设置见 [OBS-SETUP.txt](./OBS-SETUP.txt)。本轮没有验证实际 OBS 安装。

原有操作继续保留：

- 九宫格方向、分组眼口眉动作、独立视线、22 通道滑块、全部放松、脸部／全图、看原画；18 秒演示可固定方向或巡回九方向。
- 30／60 fps 绘制请求、PNG、单帧 JSON 与无声 WebM／MP4 录像。PNG、单帧和项目导出暂停并落到目标表情端点；录像保持开始时的画幅与请求帧率，录制期间不能修改帧率。重要录像先点击“停止并保存”。
- 本机手动设置与项目 JSON。项目保存方向、22 系数、查看设置、动作节奏和跟踪设置，不嵌入画稿、片段、录像或跟踪会话；重新打开保持静止、摄像头和直播输出关闭。清理浏览器数据会影响本机存档，重要设置请下载项目。

单帧 JSON 与动作片段不同：单帧可以只给部分支持通道，缺省归零、未知通道明确忽略；动作片段要求每帧完整的 22 个支持通道。非法导入保留当前状态。

## 能力边界

九姿态是分别准备的画稿，不是连续转头模型；不同方向的身体、发型与表情幅度仍可能有绘画差异。正面眉头和眉尾共用整眉抬起稿，抿嘴为整嘴近似，没有噘嘴加左右移嘴的复合稿。正面与非正面历史嘴型冲突规则仍有差异；本轮改善衔接，没有宣称统一所有选择器语义。

表情依赖已存在的实际画稿，没有运行时生成、拉伸单图或跨稿透明叠化。本轮未接入 RIFE/FILM 补帧，没有自动抠图、完整角色透明 alpha、透明视频、虚拟摄像头、iPhone 数据接收器或任意角色绑定。原画背景保留；给 OBS 页面设置透明 CSS 不会去除画稿中的背景。

60 fps 是绘制、采集或 OBS 浏览器源的请求值，不是所有设备的保证值，也不是每秒 60 张不同画稿。绘制、摄像头推理、接收页呈现与录像编码是不同环节。本轮没有开启真实摄像头；真人跟踪质量、端到端时延、长时间稳定性与实际 OBS 效果仍需实机验证。

默认启动只读取本地 2D 素材，不下载识别模型、不申请相机或麦克风、不调用图像生成 API。旧 Luna／3D 保留于 [legacy-studio.html](http://127.0.0.1:4173/legacy-studio.html)，仅作历史兼容与回归；旧 Luna v0.13 失败试验不是当前基线，新工作台不读取其 IndexedDB 项目。

## 素材与来源

当前角色以 `assets/short-hair-v1/front.png` 及对应设计批准记录为基准。素材在开发阶段使用图像生成／编辑工具制作，来源、提示词、哈希和采用记录保留于各素材包的 `provenance.json`。清单中的 `approved` 仅承接对应记录的批准范围；完整姿态包及新增中间稿中原为 `candidate` 的部分仍是候选，不因登记、测试或版本升级自动获批。

`iteration-prep-2026-10-29/` 是本机历史交接与下载整理证据；整理状态以 `cleanup-receipt.json` 为准，不应重新接入为运行素材，也不需要整体上传。旧说明见 [LEGACY-README.md](./LEGACY-README.md)，当前功能与启动方式以本 README 为准。
